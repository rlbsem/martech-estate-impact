# Establishing the model in an enterprise

Start with a decision and a boundary: which platform, which environments, which capabilities, which time horizon and which consumers are under review? A retirement claim is only as broad as its evidence collection. Record exclusions and unavailable exports before drawing a conclusion.

Interview business-accountable owners separately from technical operators. Ask what outcome stops if a particular input disappears, whether a manual or automated alternative exists, what qualifies that alternative, and who can accept the changed outcome. Do not translate “these tools connect” into “this business outcome requires both.” Use campaign walkthroughs to reveal shared identifiers, brief/status gates and attribution dependencies.

Collect inventories, orchestration definitions, scheduled jobs, integration runtime metadata, interface specifications and stewardship decisions. Retain artifact checksums, collection times, source locations and collection failures. Establish an explicit source-specific crosswalk with owners; quarantine ambiguous product/instance names. Distinguish production from nonproduction and distinguish product families from individual system instances.

Use runtime exports to corroborate declared relationships, not to equate quiet with unused. Seasonal, incident-only and low-volume flows need an appropriate historical period or an explicit review. Record expected versus observed sources and periods; do not replace an incomplete export with an assertion that it was complete.

Resolve contradictions through a named reviewer with the exact competing assertion IDs, reasons and supporting artifacts. Policy authority must fit the question: an inventory owner field does not automatically outrank the team that operates a runtime dependency. Publish a new snapshot so previous analyses remain reproducible.

For a proposed replacement, establish the required event semantics, fields and correlation keys before testing the offered interface. A matched metadata contract is the start of validation. Delivery behavior, consent handling, replay, error recovery, authorization and consumer acceptance need operational evidence outside this analytical system.

Review dependency completeness with the affected teams. Agree on qualified alternatives and on unresolved questions, not arbitrary confidence percentages. Run the proposal, inspect witnesses and residual references, correct the architecture when evidence warrants it, and publish a new assessment. Hand the target-state requirements and explicit acceptance gates to migration/cutover work. This repository neither performs nor guarantees that migration.

The bundled synthetic estate demonstrates the method with CSV/JSON exports and reviewed declarations. It does not demonstrate automatic discovery, vendor connector access, organizational adoption or production delivery history.
